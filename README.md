# 抽奖转盘｜带批量概率回测

一个纯前端、单文件的抽奖转盘程序，基于 HTML + Canvas 实现，无需构建、无任何依赖，直接用浏览器打开 `index.html` 即可运行。

## 功能特性

- **Canvas 转盘绘制**：按权重实时计算每个扇区的角度与颜色，扇区面积即中奖概率。
- **旋转动画抽奖**：10 圈减速旋转（4 秒，`ease-out-cubic` 缓动），落点由 `doOneDraw()` 统一判定，动画与判定同源，不存在"看到 A 却中了 B"的问题。
- **抽奖次数管理**：`+1 / +2 / +3 / +5` 批量加次数，点"确定"后锁定次数，剩余次数实时显示，次数用完自动禁用抽奖按钮。
- **中奖播报**：中奖结果在页面顶部红色大字播报，3 秒后自动清空。
- **中奖记录与总奖励**：逐条记录第 N 次中奖结果，并累计总积分。
- **调试模式（密码进入）**：
  - 可修改 5 / 10 / 20 / 50 / 100 积分五档权重，保存后重建扇区并即时重绘转盘；
  - 显示**单次抽奖数学期望**（按当前权重计算）；
  - 调试模式下的抽奖跳过动画，瞬间出结果，便于快速验证。
- **权重持久化**：调试模式里改的权重可真正保存，下次打开网页不用重新编辑（见下文）。
- **批量概率回测**：在调试面板内输入模拟次数（≥100），批量跑 `doOneDraw()`，输出各奖项的**实测概率**与**理论概率**对照。

## 权重持久化（重点）

权重按优先级三级生效，调试面板底部会实时显示当前用的是哪一级：

| 优先级 | 来源 | 作用范围 | 生效方式 |
| --- | --- | --- | --- |
| 1 | 本浏览器已保存 | 本机本浏览器 | 调试模式点「保存权重并更新转盘」→ 写入 `localStorage`，下次打开自动生效 |
| 2 | 仓库 `config.json` | 所有设备 | 见下方"写入仓库"步骤 |
| 3 | 代码内置默认 | 兜底 | `DEFAULT_WEIGHTS` 常量 |

### 只在本机永久生效（最快）

1. 进入调试模式 → 修改五档权重 → 点「保存权重并更新转盘」；
2. 关掉网页重新打开，权重自动恢复，无需重新编辑。

> 注意：`localStorage` 按浏览器 + 域名（或本地文件路径）隔离，换浏览器、清理站点数据、换设备都会丢失。

### 自动同步到仓库（推荐，无需导入导出）

在调试面板的「自动同步到 GitHub 仓库」区块：

1. 粘贴一个 GitHub Token，点「连接」——只需一次；
2. 连接成功后「保存权重时自动提交到仓库」会自动打勾；
3. 之后每次点「保存权重并更新转盘」，会同时：写本机存储 → 自动 commit 到仓库根目录的 `config.json`，状态栏会显示提交结果的 commit 短哈希；
4. GitHub Pages 约 1 分钟后自动用上新权重，手机/其他设备打开即是新概率。

Token 说明：

- **只存在你本机的浏览器 localStorage 里，不会写进代码、不会进仓库**（源码中不含任何明文 Token）；
- 页面通过 GitHub API 的 Contents 接口提交，会自动带上文件 `sha`，不会因并发覆盖报错；
- 换浏览器/换设备需要重新粘贴一次 Token；
- 建议用 **Fine-grained Token**，权限只勾选 `Contents: Read and write`，仓库范围只选 `lottery-wheel`，到期自动失效；
- 公用电脑用完点「清除 Token」；
- 提交失败时（Token 过期、网络问题、内容冲突），权重仍会保存在本机，状态栏会显示失败原因。

### 手动方式（Token 不便时）

1. 调试模式下点「导出 config.json」，得到当前权重的配置文件；
2. 打开 GitHub 仓库，把该文件上传/粘贴覆盖根目录的 `config.json`（或点「复制配置 JSON」，在 Web 端直接编辑 `config.json` 的 `weights` 字段）；
3. 提交后，网页（通过 http/https 打开，例如 GitHub Pages）下次打开就会加载新的默认权重。

> 说明：`config.json` 通过 `fetch` 读取，因此用 `file://` 双击打开网页时读不到（浏览器安全限制），此时只有 `localStorage` 生效；用 http(s) 打开（GitHub Pages / 本地静态服务器）才会读取仓库配置。
>
> 想让所有设备都拿到同一套权重、又不依赖 `config.json`，也可以把新权重直接写进 `index.html` 的 `DEFAULT_WEIGHTS` 常量再提交。

调试面板中的相关按钮：

- **保存权重并更新转盘**：写入本机存储；已连接 GitHub 且开启自动提交时，同时提交到仓库 `config.json`；
- **连接 / 清除 Token**：连接 GitHub（校验账号与仓库写权限）或清除本机保存的 Token；
- **恢复库中配置**：清除本浏览器保存的权重，回退到 `config.json`（读不到则回退内置默认）；
- **导出 config.json** / **导入 config.json**：跨设备搬运权重配置；
- **复制配置 JSON**：一键复制，便于直接粘贴到 GitHub 网页端编辑。


## 奖项与默认权重

| 奖项 | 权重 | 扇区数 |
| --- | --- | --- |
| 5 积分 | 20 × 4 | 4 |
| 10 积分 | 15 | 1 |
| 20 积分 | 6 | 1 |
| 50 积分 | 2 | 1 |
| 100 积分 | 0.8 | 1 |
| **合计** | **103.8** | **8** |

默认单次抽奖数学期望约为 **8.19 积分**（可在调试模式中查看实时值）。

## 使用方法

1. 下载或克隆本仓库；
2. 双击 `index.html`，或拖入浏览器窗口；
3. 先用 `+1 / +2 / +5` 添加抽奖次数，点"确定"；
4. 点"抽奖一次"开始抽奖；
5. 需要调整概率时：输入调试密码进入调试模式，修改权重 → 保存权重并更新转盘。

## 部署到 GitHub Pages（可选）

1. 打开仓库 `Settings → Pages`；
2. Source 选择 `Deploy from a branch`，分支选 `main`，目录选 `/ (root)`；
3. 保存后访问 `https://<用户名>.github.io/lottery-wheel/`。

## 说明

- 调试密码写在 `index.html` 的 `DEBUG_PASSWORD` 常量中。若用于线上真实活动，请务必改为服务端校验或直接移除调试入口，避免权重被随意篡改。
- 所有抽奖逻辑均在浏览器本地执行，刷新页面即重置全部状态（次数、记录、权重），不涉及任何后端存储。
